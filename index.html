What the platform did with each change

One row per input file. The first column is the verdict on Rhombus; the rest are what I observed in the run history, the logs and the chatbot.

Pipeline health by scenario

A run counts as a success when the scheduled run wrote a new object to GCS. Whether that object was correct is the validator's job, shown in the heat map.

Execution time and credits

Run duration from Rhombus run history, compared with the baseline run. Credits are read off the billing page after each case.

Output consistency

Same input, same pipeline, three scheduled runs. Outputs are compared by canonical hash (rows sorted, values normalised), so row order and float formatting do not count as drift.

AI builder consistency

The same /pipeline prompt sent three times in fresh projects. If the generated node lists differ, the pipeline under test depends on which attempt you got.

Chatbot diagnosis

After each failure or bad output I asked the in-app chatbot what went wrong, then applied its fix and re-ran.

Run log

Every upload from observations/runs.csv plus any validator report without a ledger line. Select a run to see its checks.
